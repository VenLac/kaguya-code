# 插件商店：移除"编程套餐"专属插件

状态：待实现 → 实现后更新。范围：插件目录（marketplace catalog）解析、商店 UI 徽标、相关协议字段。不涉及编程套餐订阅、用量面板、模型供应商、官方 MCP 鉴权与配额提示。

## 背景

商店里一批 CDN 插件的目录条目声明 `requiresPaidPlan: true`（天眼查、Wind 万得、同花顺、金融聚合搜索、交易测算等），商店卡片与详情页标题右侧显示"编程套餐"徽标。该徽标只表达"搭配编程套餐更好用"，不是安装门禁。

产品决策：软件不再提供这类插件。

## 规则

1. **目录解析入口丢弃条目。** 任何目录（官方 CDN、个人来源、本地目录、settings 内联）中，条目声明 `requiresPaidPlan === true` 时，该条目在解析阶段被丢弃：不出现在商店列表、详情、搜索、Featured，也不能被安装。
2. **只认显式布尔 `true`。** 字符串 `"true"`、`1`、缺省、`false` 都视为未声明，条目保留。理由：延续原有"目录写错不应误伤免费插件"的保守判定；反方向（误删一个本应保留的插件）与误挂徽标同级。
3. **Featured 同步。** 目录顶层 `featured` 中指向被丢弃条目的名称一并剔除，避免出现指向不存在条目的精选位。
4. **已安装的插件不被主动处理。** 不卸载、不删除数据、不改启停状态。它们继续按已安装状态工作；目录里不再有对应条目，因此不会出现在商店的可安装列表中。
5. **徽标与字段清理。** 解析不再产出 `listing.requiresPaidPlan`；UI 删除徽标组件、文案和样式变量；`@zcode/contracts` 的 `PluginStoreListing` 去掉该字段。
6. **协议兼容。** `packages/shared` 的 listing schema 是 `.strict()`，旧版 Agent（例如远程工作区）可能仍下发该字段。schema 保留 `requiresPaidPlan` 为可选并标注"已废弃，客户端忽略"，否则整个插件列表解析会失败。

## 状态所有者

| 状态             | 所有者                                                                  | 说明                                                       |
| ---------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------- |
| 目录条目是否可见 | `adapters/src/plugins/marketplace.ts` 的 `normalizeMarketplaceManifest` | 唯一过滤点。bootstrap、协议、UI 只读它的结果，不各自再过滤 |
| 已安装状态       | 现有安装状态存储                                                        | 本变更不写入                                               |

事件顺序：目录加载（任何来源）→ 解析 → 过滤 → 进入商店/安装流程。过滤发生在持久化之前的读取阶段；磁盘上缓存的原始目录 JSON 不改写，每次读取时重新过滤，因此取消过滤只需移除这一处。

## 不做

- 不移除内置插件 `image-search`（官方 Server MCP 搜图）。它没有声明 `requiresPaidPlan`，是否属于"套餐专属"待产品确认。
- 不改官方 MCP 鉴权、"无套餐/额度耗尽"提示、用量面板、订阅与购买入口。
- 不主动清理已安装插件。

## 验收

1. 目录含 `requiresPaidPlan: true` 与 `false`、缺省、字符串 `"true"` 的条目 → 解析结果只剩后三类。
2. `featured` 含被丢弃的名称 → 结果中不含该名称，其余保持顺序。
3. 目录全部条目都被丢弃 → 返回空 `plugins` 的有效 manifest，不抛错。
4. `settings` 内联的已规范化 manifest 同样被过滤（不经由 JSON 读取的路径也不绕过）。
5. 商店页不再出现徽标（`data-testid="plugin-store-paid-plan-badge"` 不存在）；类型检查通过，`PluginStoreListing` 上无该字段。
6. 旧 Agent 下发含 `requiresPaidPlan` 的 listing 时，协议 schema 仍能解析（不报错）。

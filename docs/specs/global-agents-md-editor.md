# 全局 AGENTS.md 编辑

状态：已实现并验证（见文末“验证记录”）。范围：设置页新增"全局指令"编辑入口，及其读写服务。不涉及项目级 AGENTS.md、Claude `CLAUDE.md` 迁移、运行时的指令拼装逻辑。

## 背景

运行时已经把 `~/.zcode/AGENTS.md` 作为用户级指令注入系统上下文（`adapters/src/context/index.ts` 的 `findDefaultUserInstructionFile`，读取上限 100 KB，超出截断）。但没有任何界面可以编辑这个文件，用户只能手动去文件系统改。

## 规则

1. **文件所有者是磁盘上的 `~/.zcode/AGENTS.md`。** 路径由服务端解析（`HOME` / `USERPROFILE`，与运行时相同的规则）。UI 不拼路径、不持有第二份"事实"，只展示服务返回的 `path`。
2. **服务位置。** 新增 `IUserInstructionsService`（`packages/services`），在本地 Host（`node.ts`）与远程工作区服务集合（访问器类型要求，沿用 `IMemoryService` 的做法注册本地实例）注册。设置页与记忆分区一致，**始终使用本地 Host 的服务**：编辑的是当前窗口所在 Host 机器上的 `~/.zcode/AGENTS.md`（Desktop 即本机，Web 即 server 所在机器）。远程工作区的 Agent 读取的是远程机器自己的文件，**不受本编辑器影响**，界面说明里写明这一点。
3. **读取。** `read()` 返回 `{ path, exists, content, revision }`。`revision` 是文件原始字节的 SHA-256 十六进制；文件不存在时为 `null`、`exists: false, content: ""`，不创建文件。
4. **保存。** `write({ content, expectedRevision })`：
   - 乐观并发：`expectedRevision` 与磁盘当前 revision 不一致（含读取后文件被外部创建/修改/删除）时拒绝，返回 `conflict` 与最新快照，由 UI 让用户选择覆盖或重新加载。首次保存（读取时文件不存在）以 `expectedRevision: null` 表示，磁盘上此时已存在文件同样视为冲突。用内容哈希而不是 mtime：不受文件系统时间精度影响，内容没变只是被 touch 也不算冲突。
   - 同一 Host 内的保存经串行队列执行，避免两个窗口同时保存互相穿插；比较与替换之间的极小窗口不加跨进程锁，外部进程在此窗口写入会被覆盖，属已知且可接受的边界。
   - 原子写入：写同目录临时文件再 `rename`；必要时创建 `~/.zcode`。保存成功返回新的快照，UI 以其 `revision` 作为新基线。
   - 大小：UTF-8 字节数超过 100 KB 时拒绝（`tooLarge`），与运行时截断阈值一致，避免用户写的后半截被静默丢弃。
   - 内容原样保存（不 trim、不改换行）。内容为空字符串时**写入空文件**，不删除，避免"读取后文件消失"的额外状态；运行时空内容不会生成指令段。
5. **生效时机。** 运行时在会话上下文初始化时读取一次并作为快照（`ensureContextInitialized`），所以保存后**只对新会话及冷恢复的会话生效，已在运行的会话不变**。界面在编辑器旁固定说明这一点，不做"通知运行中会话热更新"。
6. **符号链接等特殊文件。** 若 `AGENTS.md` 是指向别处的符号链接，读写都跟随链接（用户有意为之）；`rename` 原子替换会把链接换成普通文件，所以写入时若目标是符号链接，改为向解析后的真实路径写入。目标是目录或不可读/不可写时返回明确错误，UI 展示，不静默失败。
7. **入口。** 设置页"Agent 能力"分组新增 `instructions` 分区，位于"记忆"之后。组件通过 `packages/ui/src/hooks/` 访问服务，不直接 import 服务实现。
8. **编辑体验。** 等宽多行文本框；显示路径与当前字节数/上限；有未保存改动时"保存""还原"可用；超过上限时禁用保存并提示。保存成功后用服务返回的新 `revision` 作为基线。冲突时**不弹模态框**，在编辑器上方显示行内提示条，草稿保持可见，提供"覆盖保存"（以冲突时看到的磁盘版本为基线重新写入）和"载入磁盘版本"（放弃草稿）两个动作；继续编辑即为取消，不写入任何内容。有未保存改动时，侧栏切换分区、点击"返回工作区"（含侧栏底部齿轮）会先经 `settingsLeaveGuard` 弹确认；没有未保存改动时守卫不存在，其他分区的导航保持原有同步行为。遵守 `DESIGN.md`，复用 `SettingsGroupCard`、`Alert` 等现有组件，中英文文案均提供。

## 状态所有者

| 状态                 | 所有者                                  | 说明                                                   |
| -------------------- | --------------------------------------- | ------------------------------------------------------ |
| 文件内容与 revision  | 磁盘文件，经 `IUserInstructionsService` | 唯一写入路径是 `write()`                               |
| 编辑草稿、是否有改动 | UI 局部状态（组件内）                   | 不进 Zustand，不被当作服务端事实；以 `revision` 为基线 |
| 运行中会话的指令     | Agent 运行时会话快照                    | 本变更不触碰                                           |

事件顺序：打开分区 → `read()` 得 `{content, revision}` 作为基线 → 用户编辑（仅改草稿）→ `write({content, expectedRevision})` → 成功则以返回的新 `revision` 重置基线；冲突则不改磁盘并返回最新快照。并发的两次保存由服务端串行队列加 revision 比较处理；同一 UI 内保存期间禁用保存按钮，避免自己与自己冲突。

## 已知限制

- 设置页内由其他入口触发的分区跳转（例如斜杠面板的"打开设置"）不经过离开守卫，此时未保存草稿会丢失。
- 不做 beforeunload 拦截：Electron 里该事件会无提示地阻止窗口关闭。

## 不做

- 不监听文件系统变化做实时刷新（冲突检测在保存时发生）。
- 不提供项目级 / 工作区级 AGENTS.md 编辑，不提供 Markdown 预览，不提供模板库。
- 不改运行时读取逻辑与 100 KB 阈值。
- 不编辑远程工作区所在机器的文件（见规则 2）。
- 子代理页已有的"注入 AGENTS.md"开关不变。

## 验收

1. 文件不存在：`read()` → `exists:false, content:"", revision:null`；`write("x", null)` 创建文件并返回新 `revision`。
2. 读取后文件被外部修改：`write` 以旧 `revision` 保存 → `conflict`，磁盘不变，返回最新快照。外部写入相同内容（revision 不变）→ 不冲突。
3. 读取时不存在、保存前被外部创建 → `conflict`。
4. 内容 100 KB 恰好通过、多 1 字节 → `tooLarge`，磁盘不变。多字节字符按 UTF-8 字节计。
5. 保存空字符串 → 文件存在且为空；再次 `read()` → `exists:true, content:""`。
6. 目标是符号链接 → 内容写入链接目标，链接本身保留；目标是目录 → 返回错误。
7. 写入中途失败（临时文件写失败）→ 原文件不变，不遗留临时文件。
8. UI：有改动时显示未保存状态；冲突对话框三个分支行为正确；保存期间按钮禁用；切换分区带未保存改动时提示。
9. 新建会话后，上下文中的 `agentsMd` 含新内容；已运行会话不变（界面说明与此一致）。
